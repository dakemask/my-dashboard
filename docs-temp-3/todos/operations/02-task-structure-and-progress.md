# 任务结构、依赖与进度

本部分描述实例和周期模板共用的任务树。树负责层级拆分，`predecessorId` 负责同级执行顺序，权重负责进度；三者是相互独立但会共同影响完成操作的维度。

## 任务树与依赖组

每个实例或模板有一个根任务，任意任务都可以继续拥有子任务。结构编辑器一次只投影当前任务的直属子任务；打开某个子任务后，新的编辑层级以该任务为当前任务，再显示它的直属子任务。任务图则递归展示整棵树。

前置关系只存在于同一父任务的子任务之间。一个任务最多有一个直接后继，一个任务也只记录一个直接前置，因此有效关系由若干条不分叉、无环的线性链组成。每条链连同没有依赖的单个任务称为一个依赖组，组头的 `predecessorId` 为 `null`。

一个后继任务的整棵子树都受前置任务的整棵子树约束。目标叶子所在路径上，只要任一层的前置兄弟任务尚未派生完成，该叶子就不能切换为完成。

## 结构操作

结构操作以当前编辑任务的直属子任务为范围：

- 新增并列任务会建立新的依赖组；没有选中项时追加到当前任务，选中已有任务时插入到该任务所属依赖链的末尾之后。
- 新增递进任务会插入到选中任务与原直接后继之间，新任务以前者为前置，原后继改为依赖新任务。
- 删除任务会删除该节点及全部后代；它的直接后继改接到被删除任务原来的前置任务，从而保持剩余依赖链连续。
- 拖动调整的是整个依赖组，而不是链中的单个节点；依赖组只能在同一父任务下重新排序，组内前置关系不变。

任务图中的依赖组横向重排，编辑器中的直属依赖组纵向重排，两处最终调用同一个领域重排操作。任务图还允许打开节点、切换可完成叶子，以及通过上下文操作删除子树。

## 完成传播

只有实例的叶子任务直接保存 `completed`。非叶任务的完成状态恒等于所有直属子树均完成；模板中的所有节点都不保存完成状态。

叶子从未完成切换为完成时，实例在整棵根任务派生完成的瞬间写入 `completedAt`。叶子重新变为未完成时，`completedAt` 清空；只要根任务持续完成，已有完成时间保持不变。

前置任务从完成变为未完成时，其后整条依赖链的已保存完成状态会递归清空。这个传播在任务树的每一层执行，因此修改前置子树的结构或内容，只要使其从完成变为未完成，也会重置后继子树。

## 权重与进度

根任务权重固定为自动值。非根任务的 `weight` 有两种形式：负值归一为 `-1`，表示自动权重；`0` 到 `1` 表示固定权重。

同一父任务下，固定权重总和不超过 `1`。存在自动权重时，剩余权重由所有自动任务均分；全部为固定权重时，有效 payload 中的总和等于 `1`。

用户把某个任务改为固定权重时，系统先保留仍可吸收剩余额度的自动任务。若新的固定值与现有分配冲突，其余兄弟任务按修改前的有效权重比例缩放，共同填满剩余额度。删除任务后，如果剩余任务全部使用固定权重，它们会按原比例重新归一到总和 `1`。

叶子进度为 `0` 或 `1`，非叶任务进度是直属子任务递归进度的有效权重和。进度与完成判定不是同一规则：零权重的未完成任务不增加进度损失，但仍会阻止父任务完成。
