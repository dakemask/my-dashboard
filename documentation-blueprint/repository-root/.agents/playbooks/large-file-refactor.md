# 大文件连续代码搬移手册

## 何时阅读

只有同时满足以下条件时阅读：

- 需要从一个大文件移动连续代码块到新文件；
- 移动正文不改写，仅在之后调整少量 import/export；
- 使用普通 patch 会重复传输大量原文并增加截断或误改风险。

小范围编辑、非连续抽取、需要改写逻辑或目标文件已经包含正文时，不适用本手册，直接使用正常 patch。

## 安全目标

机械搬移必须保证：

- 源范围由唯一首尾锚点确定，不靠目测行号；
- 目标文件不存在或明确为空，不能用强制写入覆盖用户内容；
- 目标写入成功后才从源文件删除；
- 移动正文不进入命令参数和工具输出；
- 机械阶段不同时修改业务逻辑；
- 完成后使用正常 patch 调整少量依赖关系；
- diff 能清楚显示“移动 + 小范围接线”，没有无关格式化。

## 第一步：确认范围

使用 `rg -n` 查找唯一的开始和结束锚点，记录一次包含首尾的精确范围。再次检查范围内是否含有应留在原文件的导入、共享常量或相邻职责。

## 第二步：机械搬移

Windows 当前环境使用 Git for Windows 自带的 Ex 静默批处理完成“写入目标 → 确认成功 → 删除源范围 → 写回源文件”。该命令在受限 sandbox 中可能因 MSYS signal pipe 权限失败，因此满足本手册条件后直接申请沙箱外权限，不先做一次已知会失败的试跑。

[技术占位：这里放经过验证的 `D:\Git\usr\bin\ex.exe` 命令模板，包括 `-Nu NONE`、禁止 `write!`、分别检查目标写入和源写回错误，以及明确的 source/target 参数位置。模板本身不包含任何业务正文。]

如果目标写入失败，源文件必须保持未删除状态。不要用跨 shell 拼接出的删除或移动命令补救；先只读检查两个文件的实际内容，再决定恢复步骤。

## 第三步：调整接线

机械搬移确认成功后，使用正常 patch 完成：

- 新文件所需 import；
- 新导出及原文件 import；
- 必要的可见性或类型调整；
- 删除机械搬移后遗留的空行或无效注释。

不要顺手重命名大量符号、格式化整个文件或改变逻辑。需要进一步重构时，把它作为后续可独立审阅的步骤。

## 第四步：检查

- 确认目标文件只包含预期范围；
- 确认源文件只删除了该范围；
- 搜索原符号的定义和引用，排除重复定义与遗漏导入；
- 检查 diff 中没有整文件换行、编码或格式化噪音；
- 根据 [验证规范](../conventions/verification.md) 决定是否运行测试和构建。

## 文档同步

代码从一个文件搬到另一个文件通常不改变产品或公共契约，因此默认不更新模块长期文档。只有原文档曾把该文件作为少量稳定技术锚点时，才修正链接；不得新增完整文件职责表来记录搬移结果。
