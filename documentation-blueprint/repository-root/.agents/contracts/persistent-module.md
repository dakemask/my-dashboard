# 持久化模块公共契约

## 何时阅读

修改持久化模块的 payload、event、definition、codec、历史策略、`settle`、`project` 或 SDK 接线时阅读。创建新持久化模块时也要阅读。

纯 UI、CSS、文案、模块内部无行为重构不需要阅读。修改 Shared 内部时还需另读 [Shared 维护](../platform/shared.md)。

## 非技术摘要

每个持久化模块只负责自己的业务数据和用户动作。Shared 负责把完整业务数据安全地保存在当前设备，并在账户模式下与私人 GitHub 仓库同步。模块不能绕过 Shared 另建存储或同步路径。

这份契约描述模块能依赖的可观察行为，不复制 TypeScript 接口，也不解释 Shared 内部如何实现。

## 数据边界

持久化页面同时存在四类状态：

| 状态 | 示例 | 是否进入 payload |
| --- | --- | --- |
| 用户正在进行的实时状态 | 草稿、焦点、选择、拖拽、动画、pointer | 否 |
| 完整业务 payload | 恢复全部业务内容所需的数据 | 是 |
| 当前页面 event 历史 | 已完成且可逆的业务动作 | 否，只存在于本次页面会话 |
| Shared 系统状态 | profile、保存时间、revision、pending、conflict、编辑锁 | 否，由 Shared 管理 |

只看 payload 就必须能够恢复业务内容，不能再依赖 DOM、历史队列或同步状态补齐。payload 不得包含 token、系统 revision、冲突、焦点或临时交互。

模块负责完整校验自己的 payload。需要保存的业务变化必须能够改变稳定内容标识；相同业务内容必须产生相同内容标识和相同远端受管文件。

## Event 与会话历史

- event 表示用户已经完成、能够理解的一次业务动作，不表示每个 DOM event。
- 输入中的每个字符、拖动中的每次 pointermove、动画帧和纯选择变化通常不进入历史。
- 每个 event 必须能从动作前后的 payload 得到可靠 inverse；apply、invert、validate 和内容标识计算不能修改输入。
- 语义上没有改变 payload 的动作不进入历史，也不删除已有 redo 分支。
- 保存成功不清空会话历史；刷新页面后从已保存 payload 建立新的空历史。
- 历史容量由模块按 event 的典型大小和实际撤销需求决定，不能因为其他模块使用某个数字就照抄。

## 实时交互边界

模块向 Shared 提供两类行为：

- `settle(reason)`：保存、同步、远端变化、撤销或重做到来前，提交一个有效草稿或取消未完成交互；最多返回一个完整 event。
- `project(payload, reason)`：初始化、撤销或重做后，依据完整 payload 重建业务投影，并清理已失效的实时状态。

模块必须在自己的 `persistence.md` 中记录任何反直觉的 settle/project 决定，例如“自动保存不能结算刚开始的下一次文字编辑”或“远端变化期间有效草稿必须先提交”。普通、可从 controller 直接看出的接线不需要写入长期文档。

## 本地保存

- 本地保存只保存当前完整 payload，不保存 event 队列或实时页面状态。
- 保存前 Runtime 按模块规则执行 settle。
- 成功后才推进本地保存基线；失败时 payload、历史和旧基线保持可继续重试的状态。
- `dirty === false` 只说明页面内容已经保存到本机，不代表已经上传到云端。
- 自动保存、保存失败提示和重试入口由模块负责；Shared 负责原子本地存储和公共阻塞能力。

## 云端同步与冲突

账户模式下，完整本地 payload 与完整云端 payload 只有四种判断：

| 云端变化 | 本地变化 | 结果 |
| --- | --- | --- |
| 否 | 否 | 保持一致 |
| 否 | 是 | 保留本地，等待用户上传 |
| 是 | 否 | 接受云端并建立新的页面会话 |
| 是 | 是 | 建立可跨刷新的冲突，不自动覆盖或合并 |

- 上传、拉取、冲突方向确认、版本状态和同步结果由 Shared 公共 UI 负责。
- 模块只能提供同步前业务门禁，例如“存在草稿时暂不允许上传”；门禁不能自行实现第二套同步流程。
- 冲突只允许用户明确选择本地覆盖云端或云端覆盖本地。
- 已保存但未上传、上传结果待确认和冲突是不同状态，UI 不得混为一类。
- 模块不得直接访问 GitHub、revision、pending、profile 或编辑锁。

## Schema 演进

只有确实需要兼容既有业务格式时才声明 schema 迁移。版本元数据由 Shared 保存，不进入业务 payload 或 event。

- 迁移逐版本、确定、无副作用，不修改输入；
- 来源版本不明确、版本高于当前代码或迁移失败时必须停止，不能猜测旧数据形态；
- 本地原数据在完整迁移和校验成功前不能被覆盖；
- 已存在真实数据的模块首次接入版本管理或改变格式前，必须获得用户明确迁移决定；
- 实际迁移任务还必须阅读 [Schema 迁移手册](../playbooks/schema-migration.md)。

## 模块禁区

业务模块不得：

- 直接读写 IndexedDB、GitHub、token、revision、编辑锁或 Shared 内部对象；
- 通过修改 `runtime.current` 或私有 payload 绕过 event 推进业务状态；
- 把系统状态、实时状态或凭据混入 payload/event；
- 自行实现账户管理、同步四象限、冲突合并、全页云端遮罩或第二套同步 UI；
- 在错误提示中展示捕获异常的序列化内容、原始 GitHub 响应、请求头或 token。

## 公共契约变化

删除、改名或改变 Shared 根出口的可观察语义，改变保存/同步失败保证，或改变外部数据格式，都不是普通内部重构。必须先取得用户允许，同时检查公共契约、Shared 维护文档、受影响模块持久化说明和现有测试是否需要更新。
