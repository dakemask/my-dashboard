# 全局 UI 与交互规范

## 何时阅读

修改任意页面的样式、图标、焦点、键盘行为、弹窗、反馈或内联编辑时阅读。

纯业务数据、codec、同步算法或无界面的内部重构不需要阅读。模块独有的交互语义仍由该模块的 `product.md` 决定；本文不取代模块产品说明。

## 规范的目标

跨模块 UI 应当让相同动作拥有相近的可见和可访问行为，但不建立庞大的统一设计系统。模块可以拥有自己的布局、颜色和视觉性格，只统一容易造成误操作、布局跳动或无障碍缺失的部分。

## 图标与按钮

- 适合图标表达的工具栏动作、重复操作和紧凑操作使用 IconPark 的 `@icon-park/svg`，不从运行时 CDN 加载。
- 纯图标按钮必须同时提供准确且一致的 `aria-label` 和 `title`；图标本身不得成为重复朗读的可访问名称。
- 不常见、方向含糊或后果较重的动作不能只依赖图标猜测，应该增加可见文字或在上下文中提供清楚说明。
- 禁用状态不仅改变颜色，还必须真正阻止操作，并保持可辨识度。
- 图标尺寸、按钮高度和具体色值由模块样式持有；除非用户明确要求跨模块统一，不写入长期规范。

## 无感内联编辑

- 进入和退出编辑不得造成周围布局跳动。
- 同一段文字在只读态和编辑态保持基本一致的字体、字号、行高、换行宽度、内外边距和占位空间。
- 优先复用同一个输入控件或稳定 DOM 节点；若必须切换节点，最终用户看到的尺寸和落点仍应稳定。
- 校验失败时保留用户输入、编辑位置和明确错误，不用布局变化暗示失败。
- 焦点提示可以变化，但不应通过新增会占据布局的边框改变组件尺寸。

## 对话框与破坏性操作

- 删除、覆盖云端、丢弃有效草稿等难恢复动作必须在页面内清楚确认，文案说明将失去什么以及方向是什么。
- 有取消和确认时，键盘初始焦点落在安全动作上。破坏性确认排在动作组最后，并使用清楚的动词，不只写“确定”。
- Escape 和点击遮罩只在当前过程可以安全取消时关闭；保存、迁移或其他不可中断阶段不得伪装成可取消。
- 关闭后尽量把焦点归还给触发控件；触发控件已不存在时，移到仍然合理的页面位置。
- 不使用浏览器原生 `confirm` 代替需要方向说明、焦点恢复或忙碌状态的产品流程。

[技术占位：在这里记录项目共用 dialog 焦点圈、focus trap、遮罩事件和销毁清理的稳定实现边界；如果没有共用实现，就不虚构 API。]

## 键盘、输入法与指针

- 输入控件聚焦时，默认保留浏览器的文字编辑快捷键；模块明确声明的业务快捷键除外。
- 处理 Enter、Escape、撤销重做或快捷键时必须考虑输入法 composition，不能在组词期间误提交。
- 只能悬停才能发现的操作需要键盘或可见按钮替代路径。
- 拖拽过程中出现的实时预览不是业务提交；取消、pointercancel 或页面结算后应恢复到最近一次已提交状态。
- 键盘焦点必须可见。只在键盘导航时显示的 `focus-visible` 样式可以与鼠标焦点不同。

## 反馈与保存状态

- 短暂成功和普通信息可以自动消失；需要用户修正的字段错误、未保存状态和不可恢复失败必须持续显示，直到问题解决或用户明确关闭。
- 普通信息使用非打断式状态语义；错误使用能够及时被辅助技术感知的语义，但不能让同一错误被多个区域重复播报。
- “页面尚未保存到本机”和“已保存但尚未上传”是不同状态，任何模块都不得混用。
- 自动保存紧随业务动作时，不必闪现一次瞬时成功提示；失败必须留下可重试入口。
- toast 的精确持续时间不是全局产品契约，除非用户以后明确要求统一。

## 页面验收要点

涉及上述交互时，交付说明至少提醒用户观察：

- 编辑前后是否发生跳动；
- 纯图标按钮是否容易理解并能通过键盘聚焦；
- 取消、校验失败和破坏性确认是否保留正确状态；
- 输入法、文字撤销和模块快捷键是否互不干扰；
- 保存失败与尚未上传是否被正确区分。

具体页面布局和视觉效果仍由用户验收，本文不把一次页面截图固化为全局规范。
