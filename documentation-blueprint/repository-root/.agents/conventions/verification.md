# 验证规范

## 何时阅读

任务涉及复杂逻辑、跨文件行为、构建入口、依赖、Shared、数据格式，或需要决定是否运行测试和构建时阅读。纯讨论和只读评审无需阅读。

## 验证原则

验证范围按风险决定，不按改动文件数量或文档形式机械决定。目标是检查本次改动最可能破坏的结果，不把任务扩展成未经授权的全面测试工程。

## 默认分级

### 无需执行命令

- 只修改说明文字或示例文档；
- 用户明确目标下的简单 CSS 数值或静态文案修改；
- 不改变代码的只读分析、诊断或评审。

仍需检查 diff，确认没有误改其他文件、无冲突标记、Markdown 链接或语法明显错误。

### 定向检查

- 局部 TypeScript 重构但不改变公共行为；
- 单一模块内的业务修正；
- HTML 入口、导入路径或 CSS 分区调整。

优先运行已有且直接覆盖该区域的检查。没有现成定向命令时，不自行创建临时测试文件冒充长期验证。

### 完整项目检查

涉及复杂开发、跨模块公共行为、Shared、数据格式、构建入口或依赖时运行：

```powershell
npm test
npm run build
```

Vite 和 Vitest 需要启动 esbuild 子进程。当前 Windows 环境中应直接申请沙箱外权限运行，避免先在受限 sandbox 中重复失败。

## 测试文件与真实数据边界

- 未经用户或既有任务内容允许，不新增测试文件，也不修改现有测试文件来改变验收标准。
- 所有 GitHub、IndexedDB、认证和同步自动测试必须使用 fake、mock 或隔离测试数据，绝不访问真实 `my-dashboard-data`。
- 不为了让测试通过而降低产品规则、跳过安全检查或改写与本次任务无关的断言。
- 发现现有测试与用户明确的新行为冲突时，先报告冲突并取得修改测试的允许。

## UI 与人工验收

实际页面观感和复杂手势默认由用户验收。Agent 可以提供短小、与本次改动直接相关的验收清单，但不得在没有允许时自行扩大到浏览器矩阵、真实账户、真实仓库或数据迁移验收。

若任务需要自动化浏览器、截图对比或新增视觉测试，应先说明目的、范围和会产生的文件，再取得用户允许。

## 结果报告

交付时只报告实际执行的验证及结果。未执行的命令不要写成“应当通过”；如果因为权限、环境或任务范围没有执行，直接说明原因。
