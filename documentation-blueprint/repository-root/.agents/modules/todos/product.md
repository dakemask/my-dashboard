# 待办产品行为

## 何时阅读

修改待办实例、子任务、递进关系、进度、日期、排序、周期规则、编辑流程或用户可见保存行为时阅读。

只改 payload、event、codec、schema 或 runtime hooks 时读同目录的 [persistence.md](./persistence.md)。纯样式修正若目标明确，只读全局 UI 规范。

## 产品目的

待办模块把一个顶级事项拆成递归子任务，并用同级递进链、占比进度、提醒/截止时间和独立周期规则管理执行顺序。普通待办实例和周期模板都使用同一套任务树语义。

模块不提供标签、多人协作、自动上传、云端自动合并、子任务独立日期或后台 Service Worker。周期补建只在待办页面成功启动、重新获得焦点或跨过周期边界时发生。

## 任务树与递进关系

- 每个顶级待办拥有一棵递归任务树；根任务没有同级前驱。
- 同一父任务下的直接子任务可以组成若干条递进单链。
- 每个节点最多一个同级前驱和一个同级后继；不能跨层引用、引用不存在节点或形成环。
- 新增并列项创建没有前驱的同级任务；新增递进项插入当前任务与原后继之间。
- 删除链中任务会删除其后代，并把原前驱和后继重新连接。
- 拖动链中任意节点都代表移动整条真实依赖组，只调整同级组之间的顺序，不改变链内依赖。
- 主任务图和周期模板编辑器必须使用相同的依赖组判断，不能各自实现不同的拖动语义。

非叶子任务的完成状态由全部后代推导，不能直接勾选。叶子任务只有在其前驱整棵子树完成后才能勾选。取消一个前驱会级联取消它之后的全部后继及其子树，避免出现后置任务完成而前置任务未完成。

## 占比与进度

- 根任务不参与同级占比分配。
- 子任务占比可以是明确的 `0～1`，也可以选择自动分配。
- 存在自动项时，先扣除明确占比，剩余部分在自动项之间均分。
- 全部子任务都明确指定占比时，总和必须为 1。
- 叶子进度为未完成或完成；父任务按直接子任务的有效占比递归加权。
- 占比为 0 的未完成子任务虽然不增加数值进度，仍会阻止父任务被视为完成。

负数、规范化值和浮点容差属于领域实现。用户可见的长期规则只有“明确占比 + 自动均分余额”和“所有子任务仍参与完成判断”。

## 提醒、截止与排序

- 新建普通待办默认立即提醒，截止时间默认为无限远。
- 用户可以输入本地日期时间或非负相对天数；相对值在设置时一次性转换为绝对时间，之后不会随当前日期漂移。
- 提醒不得晚于截止。后设置的字段优先，必要时把先设置字段校正到同一时间。
- 明确的负数截止表示无限远；负数提醒在提交时表示当前时间。
- 不完整日期允许按从年到分钟的前缀输入，缺失部分取最早合法值；非法范围按产品既有规则夹取，而不是直接产生另一种日期解释。

主列表排序分组为：

1. 已截止且未完成；
2. 已提醒、未截止且未完成；
3. 尚未提醒且未完成；
4. 已完成。

组内分别强调逾期最久、最早截止、最早提醒和最近完成。顶级状态使用稳定的危险、提醒、未来和完成视觉语义，全部子任务继承顶级状态，不按子任务自己计算日期颜色。

## 周期规则

- 周期模板保存每周或每月规则、没有完成状态的任务树模板，以及已经生成到哪个期次的游标。
- 每周实例从本地周一 00:00 到下周一 00:00；每月实例从本地月初 00:00 到下月初 00:00。
- 页面离线期间遗漏的期次在下一次符合触发条件时逐期补建。
- 周期生成的实例就是普通实例，不会因为自己带有来源信息而继续生成下一期。
- 删除实例不回退周期游标，因此不能通过删除让同一期被重复生成。
- 修改或删除模板不追溯改变既有实例。
- 用户编辑周期实例后，可以只保存这一实例，也可以把名称、完整结构、递进和占比覆盖回来源模板。

本地时区、夏令时和月长度边界必须由日期领域代码统一处理，UI 不得自行计算另一套周期。

## 用户操作与编辑流程

- 主页面添加普通待办；周期模板在独立管理弹窗中创建和编辑。
- 展开待办后显示完整任务图；每个待办分别记住当前页面会话中的横向位置。
- 主任务图按完整子树显示父子连线和递进关系；拖动时预排整个依赖组，并在接近边缘时自动滚动。
- 编辑器只显示当前任务的直接子任务，使用紧凑单层结构；更深层级通过打开对应子任务继续编辑。
- 编辑内容只由明确“保存”提交；关闭、Escape 和遮罩点击在可安全取消时丢弃草稿。校验失败保持打开并保留输入。
- 删除任务和待办都使用页面内方向清楚的确认流程。
- 可点击、文字编辑、拖动和平移区域使用与动作相符的光标，但具体尺寸和色值由样式代码持有。

对话框按钮高度、toast 毫秒数、滚动条隐藏方式和 SVG 线条坐标不属于长期业务规则，除非用户以后明确要求锁定这些视觉参数。

## 保存与撤销

- 每个完成动作、周期补建、撤销或重做后立即尝试保存到本机。
- 业务命令一旦成功就保留新的待办数据；随后的自动保存失败只显示持续未保存状态和重试入口，不能把业务命令误报为失败或回滚。
- 页面使用 `Ctrl+Z` / `Ctrl+Y` 执行业务撤销重做，不显示重复按钮；输入控件聚焦时保留浏览器文字历史。
- 没有账户时只显示本地保存状态；账户模式的上传、拉取、版本和冲突由 Shared 公共 UI 处理。
