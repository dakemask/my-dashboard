# 待办持久化决定

## 何时阅读

修改待办 payload、实例/规则实体、event、历史、definition、codec、schema、周期补建提交、`settle` 或 `project` 时阅读，并同时阅读 [公共持久化契约](../../contracts/persistent-module.md)。

用户可见的任务、日期和周期语义见 [product.md](./product.md)。

## 模块边界

- `moduleId` 固定为 `todos`，对应既有本地隔离键和 `data/todos/` 远端目录。
- 完整 payload 包含普通/周期生成的实例集合和周期规则集合。
- 实例持有顶级日期、完成时间、展开状态、来源规则/期次和完整任务树。
- 周期规则持有模板任务树、周期类型和已生成期次游标。
- schemaVersion、revision、保存时间、pending、conflict、页面选择、弹窗草稿、拖动态和 event 历史不进入 payload。

展开状态有意进入 payload，以便保存和跨设备恢复；任务图的横向滚动位置和拖动预览只属于当前页面会话，不进入 payload。

## 任务树持久化不变量

- 任务身份在其 payload 内稳定且唯一；根、直接子任务和后代层级完整。
- 同级前驱引用只能形成若干单链，不能悬空、跨层或成环。
- 非叶子完成由后代推导，不以可互相矛盾的布尔字段重复保存。
- 周期模板不保存叶子完成状态；生成实例获得独立的完成状态。
- 日期以可跨设备解释的绝对 UTC ISO 保存；“无限远”使用明确空值，不使用某个极大日期伪装。
- 相同业务内容规范化为稳定顺序和稳定编码。

## Event 与历史

待办 event 使用实体级前后值事务表达一次完成动作。概念上包括：

- 新增、替换或删除实例；
- 新增、替换或删除周期规则；
- 一次周期补建产生的多实体变化；
- 弹窗保存、级联完成、依赖组重排等引起的完整实体替换。

一次用户可理解的级联、弹窗保存、依赖组重排或周期补建各占一步。inverse 交换实体前后状态并按安全顺序恢复，不能把一个级联拆成大量子 event 让用户逐步撤销到非法中间状态。

历史容量保持 200。待办日常编辑频率高，而一次 event 通常以受影响实体为边界；改变容量前需要重新评估大型任务树替换的内存成本。

## 周期补建与保存边界

- 周期补建只在产品说明列出的触发时机检查。
- 同一次检查发现多个遗漏期次时，生成结果作为一个完整业务动作提交，避免只保存一半期次。
- 生成成功后才推进规则游标；删除已生成实例不回退游标。
- 业务动作提交后立即尝试本地保存；保存失败保留 event 结果和可重试状态。
- 页面重复获得焦点或多个调度信号同时到达时，不得为同一期创建重复实例。

## `settle` 与 `project`

`settle` 在公共保存、上传、拉取、远端变化、撤销和重做到来前处理有效弹窗草稿，并取消未完成拖拽、预排和自动滚动。一次弹窗保存涉及的完整实例或规则变化必须形成一个 event；无效草稿保留还是取消，取决于命令是否由用户主动触发以及产品门禁结果。

`project` 在初始化、撤销和重做后以完整 payload 重建业务视图，清理已不存在的选择、弹窗和拖动状态。列表排序、父级完成和进度必须从 payload 统一推导，不能从旧 DOM 继续沿用。

[技术占位：分别记录 controller hooks、编辑器草稿抽取和 keyed task graph 投影的入口；局部 DOM 更新算法不进入本文。]

## 远端编码与 Schema

- 远端只管理 `data/todos/todos.json`。
- 文件包含完整实例和周期规则，采用稳定两空格 JSON 与结尾换行。
- codec 不读取或生成 Shared 的 `revision.json`；decode 只解析原始业务 JSON，当前 schema 校验在 Runtime 完成迁移后执行。
- 相同业务 payload 必须产生逐字节相同的 `todos.json`。

当前业务 schema 为 v1。版本由 Shared 保存，不进入 `todos.json` 或 payload。缺失版本不能自动解释为 v1；任何真实旧数据转换必须按 [Schema 迁移手册](../../playbooks/schema-migration.md) 单独决定。
