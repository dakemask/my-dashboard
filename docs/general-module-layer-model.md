# 通用模块分层模型

## 目的

本文件定义适用于交互式前端模块的通用状态模型。Mind Map、碎片想法以及未来的同类模块可以共享此模型；各项目只需替换自身的业务 schema 与策略。

## 两个维度

模块架构包含两个相互垂直的维度：

1. **状态归属层**：某类状态存在哪里、存活多久、谁能写入；
2. **传递机制层**：命令如何路由、数据如何提交、保存、初始化和同步。

## 状态归属层

```mermaid
flowchart LR
  U["用户命令层"] --> R["实时状态层"]
  R --> S["数据暂存层"]
  S --> L["本地数据层"]
  L <--> C["云端数据层"]
```

### 用户命令层

表达用户意图，例如输入、点击、快捷键、拖拽、保存。它是控制层，不持有业务文档数据。主要与实时状态层直接交互。某些场景下实时状态层较薄时，可视为与数据暂存层直接交互。也通过保存、同步等按钮控制其他层之间的数据传递行为。
虽然作为状态归属层，但没有可用代码或程序定义的状态，代表用户意图状态。

### 实时状态层

持有当前标签页中用户直接控制和即时观察到的状态。它可以含有可持久化数据的实时表现，也可以含有选中、悬停、焦点、动画、拖拽中间值等纯交互状态。

实时状态层只服务当前会话，不能直接写本地数据层或云端数据层。

### 数据暂存层

持有当前会话中准备保存的可持久化数据类型的数据（也就是与本地数据层、云端数据层相同schema的数据） + `dirty` 标签。并且不仅持有单份数据，而是持有本地数据层数据 + 后续操作队列，以实现ctrl+z和ctrl+y。

和实时状态层、本地数据层交互的是队列中的某个状态，不进行ctrl+z时默认为最新的状态。非最新状态下被实时状态层或用户操作层变更数据后，会丢弃另一条分支的操作。

`dirty` 标签不跟随队列，只由数据暂存层与本地数据层当前数据的差别决定。

关闭或重载标签页后消失。

### 本地数据层

IndexedDB作为实现。

### 云端数据层

GitHub私人仓库作为实现，所有模块共用一个仓库，每个模块有自己的文件夹，位于data/。

## 传递机制层

| 机制       | 标准方向                       | 说明                                       |
| ---------- | ------------------------------ | ------------------------------------------ |
| 命令分发   | 用户命令 → 实时状态或数据暂存  | 将用户意图转成明确的状态操作。             |
| 实时提交   | 实时状态 → 数据暂存            | 将可保存的实时变更纳入文档，并标 dirty。   |
| ctrl+z队列 | 数据暂存 → 实时状态            | 用队列中不同位置的暂存数据初始化实时状态。 |
| 本地保存   | 数据暂存 → 本地数据            | 提交 dirty 数据到设备持久化存储。          |
| 初始化     | 本地数据 → 数据暂存 → 实时状态 | 从设备数据建立一个新的会话。               |
| 上传       | 本地数据 → 云端数据            | 将设备中已保存的数据提交到远端。           |
| 拉取       | 云端数据 → 本地数据            | 获取远端数据并写入设备数据。               |

## 固定的通用规则

除了上面提到的约束，以下规则在本项目的所有模块中固定：

1. 实时状态不得绕过数据暂存层直接写入本地或云端数据。
2. `dirty`、撤销和重做属于数据暂存层，不属于本地或云端数据层。
3. 本地数据是设备持久化边界；云端数据只能由本地数据层上传更新。
4. 新会话按“本地数据 → 数据暂存 → 实时状态”初始化。

## 由项目自行定义的内容

以下内容必须由每个项目或模块单独声明：

| 项目定义项   | 示例                                                           |
| ------------ | -------------------------------------------------------------- |
| 业务 schema  | 脑图节点/箭头；碎片卡片/标签/排序。                            |
| 实时状态字段 | 脑图的 resize 中间值；碎片项目的拖拽排序、筛选条件、输入焦点。 |
| 提交时点     | 每次输入、节流、失焦、拖拽结束、显式确认。                     |
| 本地存储设计 | 数据库表、索引、迁移、序列化和版本格式。                       |
| 保存策略     | 手动保存、自动保存、离线重试、保存状态展示。                   |
