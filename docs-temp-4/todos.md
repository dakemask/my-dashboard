# Todos 模块

## 模块概览

Todos 是仪表盘中的待办模块，同时支持一次性待办和按周、按月生成待办的周期模板。持久化数据只有两类顶层实体：`instances` 是用户实际执行的待办实例，`rules` 是负责生成实例的周期规则。二者都包含任务树，但生成后的实例独立于模板继续演化。

该模块不是平面清单。每个待办以根任务作为标题和整体完成状态，子任务树表达任务拆分；同一父任务下还可以形成线性的前置依赖链。进度、可完成性、展示状态和排序都由领域层计算。

运行入口是 `src/todos/main.ts`。`TodosController` 连接共享 `ModuleRuntime`、页面 UI 和领域操作；`src/todos/domain/` 是数据约束与业务规则的唯一来源；两个 Editor 管理尚未提交的实例或模板草稿；图视图和结构编辑器只负责交互投影。

## 讨论待办列表、状态或排序时

待办实例包含创建时间、提醒时间、可选截止时间、完成时间、展开状态、来源周期信息和一棵任务树。根任务是否完成决定整个实例是否完成，`completedAt` 必须与这个派生结果一致。展开状态属于实例数据，会随其他业务数据一起保存。

实例的展示状态是一个四状态模型：

| 状态 | 含义 |
| --- | --- |
| `pending` | 尚未到提醒时间 |
| `reminded` | 已到提醒时间，但未到截止时间，或没有截止时间 |
| `overdue` | 未完成且已到截止时间 |
| `completed` | 根任务已经完成 |

完成状态优先于时间状态。未完成实例随时间从 `pending` 进入 `reminded`，有截止时间时再进入 `overdue`；取消完成后会重新按当前时间计算状态。列表按 `overdue`、`reminded`、`pending`、`completed` 分组排序，组内时间顺序由 `domain/dates.ts` 统一定义。

日期以规范 UTC ISO 字符串持久化，但用户输入、按天换算以及周/月边界按本地时间计算。涉及状态、排序或日期需求时，应先看 `domain/dates.ts`，不要在 Controller 或视图中另建判断。

## 讨论子任务、依赖或进度时

`TodoTask` 同时用于实例任务树和周期模板树。节点包含名称、权重、直接完成值、同级前置任务和子节点。根节点没有前置任务且权重固定为自动值。

完成规则如下：

- 只有叶节点保存可切换的 `completed`；非叶节点的完成状态由全部子节点递归派生。
- 一个叶节点只有在自身以及各级祖先所在依赖链的前置任务都已完成时，才能从未完成切换为完成。
- 已完成的前置任务重新变为未完成时，其后整条依赖链的已存完成状态会被清除。这一规则同样适用于结构编辑使前置任务重新变为未完成的情况。

`predecessorId` 只允许引用同一父任务下的另一个节点。同级依赖必须是若干条互不分叉、无环的线性链：一个节点最多有一个直接后继。界面中的拖动单位是整条依赖组，而不是链中的单个节点，并且只能在同一父任务下重排。

权重在每一组直接子节点内计算。负值表示自动权重，显式权重范围为 0 到 1；显式权重先占用份额，剩余份额由自动权重节点均分。如果没有自动权重，显式权重之和必须为 1。任务进度是子节点进度按有效权重递归汇总的结果。

新增、删除、替换、重排、切换完成和调整权重都集中在 `domain/tasks.ts`。这些操作除了改树，还负责维持依赖链、完成回退和权重约束；需求不应绕过它们直接拼接任务树。

## 讨论新建、编辑或删除时

实例编辑和模板编辑都是草稿事务。Editor 持有基线与草稿，负责表单和任务结构；Controller 持有当前已接受的 payload 和 Runtime。用户在任务树中进入更深节点时，当前字段先合入草稿，再用同一份草稿打开下一层编辑器；真正保存时才生成新的完整 payload 并提交。

编辑实例根任务时处理名称和提醒/截止时间，编辑子任务时处理名称和权重。结构编辑器展示当前编辑节点的直接子任务，可增加并行任务、增加后继任务、删除任务和重排依赖组。模板编辑使用同一套树操作，但模板不保存任何完成状态。

周期生成的实例通过 `sourceRuleId` 和 `sourcePeriodKey` 记录来源。普通编辑只修改该实例；“保存并覆盖周期模板”才会把当前实例的任务结构复制回来源规则。覆盖时会生成全新的模板任务 ID，并清除全部完成状态，不会改写已经生成的其他实例。

删除周期规则只停止未来生成，既有实例保留。删除实例不会影响来源规则。

## 讨论周期待办时

周期规则由周期类型、模板树和生成游标组成。目前周期只有 `weekly` 与 `monthly`。周周期从本地时间周一零点开始，月周期从本地时间每月一日零点开始；生成实例的提醒时间是周期起点，截止时间是下一周期起点。

周期生成流程是：

1. 新建规则时，规则与当前周期实例在同一次提交中创建。
2. 切换规则周期时，初始化新周期类型的当前周期；普通模板修改只影响以后生成的实例。
3. 模块启动、窗口重新获得焦点、页面重新可见以及下一个周期边界到达时，检查并补齐游标之后缺失的周期。
4. 每次生成都会复制模板、分配全新的实例和任务 ID、清除完成状态，并推进对应周期的游标。

`generatedThrough` 分别保存周、月游标，是“每条规则每个周期至多生成一次”的依据。周期生成依赖页面运行时机和边界定时器，不是独立后台任务。相关需求以 `domain/recurrence.ts` 的周期计算和生成函数为准，Editor 与 Controller 只决定何时触发和提交。

## 讨论撤销、保存或云同步时

Todos 通过共享模块运行时持久化，不直接管理 IndexedDB 或 GitHub。`definition.ts` 将模块注册为 JSON 模块：当前 schema 版本为 1，历史容量为 200，编码结果只包含 `todos.json`。

一次业务修改先构造并校验新的完整 payload，再由 `createTodosEvent` 计算单个 `change-entities` 事件。事件分别记录实例和规则的实体级前后值及数组位置，因此任务树内部修改表现为其所属实例或规则的一次实体替换。事件可校验应用、反转并用于撤销/重做。

命令流程固定为：Runtime 接受 `dispatch`、`undo` 或 `redo`，Controller 立即采用 Runtime 返回的 payload，然后执行本机保存。结果分为三类：

- 命令失败：业务状态不变。
- 命令成功且保存成功：流程结束。
- 命令成功但保存失败：保留已经接受的业务状态，标记本机保存失败并等待重试，不回滚命令。

存在编辑对话框或拖动交互时，显式同步操作会被阻止；Runtime 尚有未保存命令或本机保存失败时也不能同步。Runtime 在远端变化等流程中要求结算草稿时，有效草稿会先转为事件，无效草稿会关闭并恢复到保存前状态。投影回调则以 Runtime 给出的 payload 整体替换 Controller 当前状态。

## 讨论任务图或交互界面时

列表卡片和周期模板预览使用 `TaskGraphView` 展示任务树；编辑对话框使用 `TaskStructureEditor` 修改当前节点的直接子任务。两者共享领域层的依赖组概念，但维护各自的 DOM 和交互状态。连线投影、拖动排序和图面平移分别由独立 UI 组件处理，Controller 负责绑定回调和把意图提交为领域变更。

实例图的展开状态持久化在实例中；模板预览的折叠状态只存在于当前 Controller 会话。界面需求如果改变业务含义，应先修改领域规则，再让两个视图消费同一结果，避免图视图与编辑器形成两套规则。

## 修改约束

- payload、事件和外部读取的数据都要经过领域校验；对象字段是精确 schema，所有实例、规则及其任务 ID 在整个 payload 内全局唯一。
- 不直接设置非叶任务或模板任务的完成状态，也不在 UI 中复制依赖、权重、进度和状态算法。
- 持久化变更统一走“构造下一 payload → 创建事件 → Runtime 命令 → 保存”路径；保存失败不能回滚已被 Runtime 接受的命令。
- 周期模板与生成实例保持单向生成关系。模板变化不追改历史实例，实例变化也不得隐式修改模板。
- 新领域逻辑放入 `domain/` 的对应语义模块。`domain/model.ts` 只是兼容门面，新代码不应继续扩大它。

## 按需求定位代码

| 需求主题 | 首先阅读 |
| --- | --- |
| 数据结构、全局不变量 | `domain/types.ts`、`domain/validation.ts` |
| 任务树、依赖、权重、进度 | `domain/tasks.ts` |
| 日期、状态、列表排序 | `domain/dates.ts` |
| 周期边界与补生成 | `domain/recurrence.ts` |
| 事件、撤销与实体顺序 | `domain/events.ts` |
| 实例或模板编辑事务 | `ui/instanceEditor.ts`、`ui/recurrenceEditor.ts` |
| 页面编排、同步门禁、定时触发 | `app/controller.ts` |
| 命令与保存失败语义 | `app/persistedCommands.ts`、`definition.ts` |
