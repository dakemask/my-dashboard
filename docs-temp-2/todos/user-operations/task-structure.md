# 任务结构、递进依赖、完成状态与进度

这是 `todos` 最需要先建立心智模型的部分：数据形状是一棵树，但每个父节点的直接子任务还会按 `predecessorId` 划分为若干线性依赖链。

## 结构模型

- `children` 表示层级从属，任意深度都允许。
- `predecessorId` 只能指向同一 `children` 数组中的另一个节点。
- 每个节点最多只有一个直接后继，所以同级依赖只能形成 `A -> B -> C` 这样的链，不能形成一个前驱对应多个后继的分叉 DAG。
- 没有前驱的节点是依赖组头；组头及沿后继关系找到的所有节点共同构成一个“依赖组”。
- 数组顺序同时承担依赖组的展示顺序，领域函数均返回新树，不原地修改输入。

## 用户编辑结构

编辑器的结构区只投影当前任务的直接子任务，并提供三个语义命令：

1. “新增并列”：未选中任务时在当前直接子任务末尾新增独立组；选中任意链成员时，在该成员所属链的尾部之后插入新的独立组。
2. “新增递进”：在选中节点之后插入一个后继；若原来已有直接后继，则把原后继改接到新节点，保持单链。
3. “删除选中”：确认后删除节点及其子树；原直接后继改接到被删节点的前驱，从而保持链连续。

点击行只选择直接子任务，点击行末入口才进入该子任务的编辑上下文。编辑器中垂直拖动、展开图中水平拖动都只移动完整依赖组，不能拆开链，也不能跨父任务移动。

## 完成状态机

只有叶节点的 `completed` 是真实存储状态；非叶节点完成与否始终由 `children.every(isTaskComplete)` 推导。

| 当前对象/条件 | 用户动作 | 结果 |
| --- | --- | --- |
| 未完成叶节点，沿根到该叶的每一级前驱都已完成 | 勾选 | 叶节点 `completed=true`。 |
| 已完成叶节点 | 取消勾选 | 叶节点 `completed=false`，并触发后继清理。 |
| 非叶节点 | 尝试勾选 | 禁止，父任务完成状态只能由子树推导。 |
| 任一路径层级上的前驱子树未完成 | 尝试勾选后继子树中的叶节点 | 禁止，完成门返回 `predecessor-incomplete`。 |
| 已完成前驱因取消勾选或结构编辑变成未完成 | 状态更新 | 同级后继链中所有节点的整棵子树递归清为未完成。 |
| 实例根由未完成变为完成 | 状态更新 | `completedAt` 设为当前时间。 |
| 实例根由完成变为未完成 | 状态更新 | `completedAt` 清为 `null`。 |

完成门会检查目标叶节点到根路径上的每一级：如果某个祖先节点本身是同级递进链的后继，则它的前驱整棵子树也必须已完成。因此“前驱锁”覆盖整个后继子树，而不仅是相邻叶节点。

结构编辑也可能破坏一个原本完整的前驱；`replaceTask`、插入和删除等路径会重新检查并清除已经不再合法的后继完成状态。不要只在复选框 handler 中实现级联规则。

## 权重与进度

- 根任务 `weight` 必须为 `-1`；非根节点的负权重会规范化为 `-1`，表示“自动分配”。
- 固定权重允许 `0..1`；同级仍有自动节点时，固定权重总和不得超过 `1`，没有自动节点时固定权重总和必须为 `1`。
- 有 `n` 个自动节点时，每个节点的有效权重为 `(1 - 固定权重总和) / n`，且余量最低按 `0` 处理。
- 非叶节点进度是 `sum(子节点递归进度 * 子节点有效权重)`，最终限制在 `0..1`；叶节点进度只有 `0` 或 `1`。
- 权重为 `0` 的任务仍参与完成状态判定，所以“进度 100%”与“任务树完成”不是同一个条件。
- 用户把某个任务改为固定权重时，若当前自动余量仍合法则保留其他存储权重；若发生冲突，则按其他任务原有效权重的比例重分剩余份额。
- 删除任务后，如果剩余节点全是固定权重，则重新归一化到总和 `1`；若总和为 `0` 则平均分配，有自动节点时保留自动分配机制。

## 拖拽与图交互的语义边界

- `dependencyGroups` 是编辑器列表和任务图共同使用的分组真相，拖动组的 ID 是组头 ID，即使用户从链中间节点开始拖动也会移动整组。
- 鼠标越过移动阈值后激活拖动；触摸图节点要求静止长按，编辑器列表使用移动激活。
- 拖动期间 DOM 只做预排序和动画，结束时仅提交 `beforeGroupId` 语义意图；领域层再次执行 `reorderDependencyGroup`，取消、Escape 或丢失指针捕获会恢复原顺序。
- 图的空白区域支持横向平移和惯性，节点交互与拖拽优先级由 `GraphPanController`、`PointerReorder` 协调。

## 主要实现链

领域真相位于 `src/todos/domain/tasks.ts`，严格结构约束位于 `validation.ts`；`TaskStructureEditor` 和 `TaskGraphView` 只投影/发出操作意图，`TodoInstanceEditor`、`TodoRecurrenceEditor` 与 `TodosController` 再把领域结果提交为载荷事件。
