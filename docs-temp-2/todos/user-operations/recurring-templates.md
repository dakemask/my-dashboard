# 周期模板与实例生成

## 模板模型

`TodoRecurrenceRule` 包含规则 ID、创建时间、`weekly | monthly` 周期、一棵全部未完成的任务模板，以及独立保存的周/月生成游标 `generatedThrough`。保留两种游标使用户切换周期后再切回来时仍能知道该周期已经生成到哪里。

## 用户管理模板

1. 点击“周期待办”打开模板管理对话框，模板列表本身被移动进该对话框展示。
2. “添加模板”创建默认每周、名称“新周期模板”、两个游标均为空的草稿。
3. 编辑模板根节点可改模板名称和周/月周期；编辑模板子节点可改名称、权重和结构，结构命令与实例一致。
4. 保存新模板，或保存一个发生周期切换的模板时，会在同一载荷事务中尝试初始化当前周期并可能立即新增一个实例。
5. 只修改模板内容而不改变周期，不会重写既有实例，也不会额外生成当前周期实例；新模板只影响以后生成的实例。
6. 删除模板只从 `payload.rules` 移除规则并停止未来生成，已经生成的实例全部保留。

模板预览默认展开，其展开/收起状态只存在控制器的 `collapsedRuleIds` 中，不持久化，也不进入撤销历史。

## 周期边界

- 每周周期按本地时间周一 `00:00` 开始，下一周周一 `00:00` 结束。
- 每月周期按本地时间每月 1 日 `00:00` 开始，下月 1 日 `00:00` 结束。
- 周期 key 由周期种类和周期开始时间组成，用于标记实例来源，但防重复的主要机制是规则的生成游标。

## 生成算法

创建的每个周期实例都具有以下语义：

- `reminderAt = period.start`，`deadlineAt = period.end`。
- `sourceRuleId` 指向规则，`sourcePeriodKey` 记录周期 key。
- 模板树被深拷贝，实例根及所有子任务获得新的 UUID，所有完成状态清零。
- 实例默认收起，`completedAt = null`，创建时间取实际生成时刻。

初始化规则时，若当前 cadence 的游标为空或早于当前周期，则生成当前周期一次并把游标推进到当前周期开始；若游标已经覆盖当前周期则不重复生成。

常规补生成从游标后的下一个周期开始，逐期生成直到包含当前周期，因此页面离线或长期未打开时不会只补最新一期，而会补齐所有遗漏的有效周/月实例。每生成一期，规则对应 cadence 的游标同步推进。

## 生成触发时机

- Runtime 首次挂接并完成页面渲染后。
- 窗口重新获得焦点时。
- 页面从隐藏变为可见时。
- 距当前最近的任意周/月边界到达时，控制器定时器再次运行。
- 新建规则或改变 cadence 的保存事务内。

如果此时有活动编辑器，后台补生成暂不提交，只重新安排边界检查；编辑结束后的其他触发会继续补齐，游标保证不会重复。

## 实例与模板的关系

生成是“快照复制”而非动态引用：后续编辑模板不改变已有实例，编辑实例也不改变模板。唯一反向写入是来源实例上的“保存并覆盖周期模板”，它用实例当前结构创建新的未完成模板树，但保留规则 ID、cadence 和游标。

## 主要实现链

`src/todos/domain/recurrence.ts` 定义周期、初始化、补生成和最近边界，`TodoRecurrenceEditor` 负责模板草稿及保存时初始化，`TodosController.#runPeriodicGeneration/#scheduleBoundary` 负责页面生命周期触发。
