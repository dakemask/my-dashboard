# 日期、派生状态与实例排序

## 日期字段

每个实例始终有 `reminderAt`，并可有 `deadlineAt`；两者以规范 UTC ISO 字符串持久化，但用户输入和周期边界按浏览器本地时间解释。

根实例编辑器分别提供“提醒日期”和“截止日期”入口，每次可选两种输入方式：

- 具体日期：输入 `YYYYMM` 到 `YYYYMMDDHHmm` 范围内的 6–12 位数字，缺失的日/时/分使用最早值，超出范围的月、日、时、分会被夹到合法范围。
- 负数快捷值：提醒日期的任意负整数表示“现在”，截止日期的任意负整数表示无限远，即 `null`。
- 相对天数：提醒日期可设为“截止日期减 N 个本地日”，截止日期可设为“提醒日期加 N 个本地日”；`N` 必须是非负整数，截止为无限远时不能反推提醒。

系统保持 `reminderAt <= deadlineAt`：若用户把提醒改到截止之后，以提醒为准并把截止拉到同一时间；若用户把截止改到提醒之前，以截止为准并把提醒拉到同一时间。

## 状态派生

`TodoStatus` 不写入载荷，而是在渲染时按当前时间和任务树完成状态计算，优先级如下：

```text
根任务已完成
  -> completed
否则 deadlineAt != null 且 now >= deadlineAt
  -> overdue
否则 now >= reminderAt
  -> reminded
否则
  -> pending
```

因此已完成实例不会再显示为逾期；无截止日期的未完成实例最多进入 `reminded`，不会进入 `overdue`。

## 列表排序

卡片先按状态分组：`overdue -> reminded -> pending -> completed`，组内排序为：

| 状态 | 主要排序键 |
| --- | --- |
| `overdue` | 截止时间升序，最早截止在前。 |
| `reminded` | 截止时间升序，无截止日期排在本组最后。 |
| `pending` | 提醒时间升序。 |
| `completed` | 完成时间降序，最近完成在前。 |

主要键相同时再按创建时间升序，最后按实例 ID 稳定排序。卡片摘要显示截止日期或“无截止日期”，提醒日期只在实例根编辑器中显示。

## 与刷新时机有关的实现事实

状态和排序会在全量渲染、相关实例局部更新及卡片重排时重新计算。当前控制器的定时器只调度周期模板边界，没有为每个提醒/截止时刻单独安排状态刷新；如果需求要求页面静置时也在时间跨界瞬间更新，需要在控制器层补充日期边界调度，而不能把 `TodoStatus` 改成持久字段。

## 主要实现链

`src/todos/domain/dates.ts` 负责解析、相对日期、先后关系、状态和排序，`TodoDateEditor` 负责具体/相对输入对话框，`TodosController` 在渲染卡片和局部更新时消费派生结果。
